# ---------------------------------------------------------------------------
#  Service_Manager - the fixtures and the cases of the cross check
#
#  One file, two readers:
#    * tools\sim\run.wsf crosscheck      (the model under cscript)
#    * modTests.Test_CrossCheck          (inside the workbook)
#
#  Both build their data from [config] and [tables], then evaluate every line of
#  [cases] and write one output line per case to
#      build\sim-crosscheck.txt   /   build\xls-crosscheck.txt
#  tools\build.vbs compares the two files line by line: the same fixture must
#  give the same answer, no matter which implementation computed it.
#
#  Line format of a case:   kind|name|arguments
#  Line format of a result: kind|name|value...   (one line per case, plans one
#  line per slot, in the same order in both lanes)
#
#  kinds: rule       -> the rule code of a booking payload ("" = accepted)
#         normalise  -> the payload as the validator normalised it
#         count / revenue / freeday / label / busy / conflict-start
#         plan       -> the slot plan of a day (what the daily grid shows)
#         config-rule     -> the rule code of the Config page ("" = it is fine)
#         config-values   -> the canonical values the page stores (eight, in the
#                            order of the sheet, joined by "|")
#         config-defaults -> the built in values of section 16.1
#         config-dates    -> the non working dates with one day added
#                            ("day|list in the cell", ISO, in order, no repeats)
# ---------------------------------------------------------------------------
